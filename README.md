# bombermangamedemo项目介绍以及相关策划案和测试报告
经典炸弹人玩法的 Unity 实现：程序化生成的网格关卡、十字范围爆炸、属性成长与无尽关卡递进。

### 核心玩法

玩家在随机生成的网格地图中移动，按空格键放置炸弹。炸弹倒计时结束后产生十字形爆炸，可炸毁可破坏墙、消灭敌人，也会误伤自己。炸毁墙体有几率掉落增益道具（提升移速、炸弹数量或爆炸范围）。消灭当前关卡所有敌人后，隐藏在某处的门会出现，进入门即可挑战下一关。

### 游戏特性

- **程序化地图生成**：每关地图尺寸、可破坏墙分布、道具位置与敌人生成点全部随机，不可破坏墙按偶数格固定排列保证关卡可玩性
- **经典十字爆炸**：爆炸沿上下左右四个方向延伸，遇到不可破坏墙即终止，爆炸范围随玩家属性成长
- **玩家属性成长**：初始 1 颗炸弹、范围 1 格、3 点 HP，拾取道具可提升移速（上限 0.2）、炸弹数量与爆炸范围
- **受伤无敌机制**：被敌人或爆炸波及后扣血并进入 2 秒无敌闪烁期，避免连续掉血
- **无尽关卡递进**：关卡越深地图越大（最大 18×15）、敌人越多（最多 20）、时间限制越紧张，难度持续攀升
- **时间压力**：每关有倒计时，时间归零扣血并重置时间，HP 归零则游戏结束

### 技术亮点

- **通用对象池系统**（`ObjectPool`）：基于枚举 `ObjectType` + 预制体映射表，统一管理墙、炸弹、爆炸特效、敌人、道具的生成与回收，避免频繁 Instantiate/Destroy
- **地图生成与回收分离**：`MapController` 用字典记录本关生成的所有对象，切关时批量回收到对象池，再按新参数重新生成
- **炸弹爆炸使用协程延时 + `Action` 回调**：爆炸结束后回调归还炸弹数量并从列表移除，逻辑解耦清晰
- **单例模式**贯穿'GameController`、`ObjectPool`、`AudioController`、`UIController`， 全局访问便捷
- 支持 PC 键盘（方向键 + 空格）与移动端虚拟摇杆双套输入方案，摇杆代码已预留可一键切换

## 一、游戏概述

### 1.1 游戏定位

本项目是经典**炸弹人（Bomberman）玩法**的Unity实现。玩家在程序化随机生成的网格地图中移动，放置炸弹产生十字形爆炸消灭敌人、炸毁可破坏墙，拾取道具提升属性（移速/炸弹数/爆炸范围），消灭所有敌人后找到隐藏的门进入下一关。关卡无尽递进，地图逐渐变大、敌人增多、时间收紧，挑战玩家的策略规划与临场反应。

### 1.2 核心体验关键词

- **策略放置**：炸弹放置位置决定杀敌效率与自身安全，需要预判爆炸范围
- **十字爆炸**：经典十字范围爆炸，遇不可破坏墙终止，范围随属性成长
- **随机地图**：每关地图程序化生成，布局不重复，重玩价值高
- **属性成长**：拾取道具提升移速/炸弹数/爆炸范围，build感强
- **无尽挑战**：关卡无限递进，难度平滑上升，追求更高关卡数
- **紧张刺激**：倒计时压力+敌人追击+爆炸连锁，单局节奏紧凑

### 1.3 目标用户

- 喜欢经典炸弹人/泡泡堂玩法的休闲玩家
- 喜欢策略规划与随机性结合的roguelike爱好者
- 移动端碎片化时间玩家（单局3-10分钟）
- PC端和移动端休闲玩家

## 二、核心玩法设计

### 2.1 核心循环

```
进入关卡 → 探索地图 → 放置炸弹炸毁墙壁/消灭敌人 → 拾取道具提升属性 → 
消灭所有敌人 → 找到门并进入 → 生成更大更难的新关卡 → 循环
```

### 2.2 玩家操作

| 操作 | 按键（PC） | 功能 |
|---|---|---|
| 移动 | W/A/S/D 或 ↑/←/↓/→ | 四方向网格移动 |
| 放置炸弹 | 空格 | 在当前格子放置炸弹 |
| 暂停 | Esc | 打开暂停菜单 |

> 移动端：虚拟摇杆控制方向，按钮放置炸弹（代码已预留，Joystick Pack集成）

### 2.3 炸弹与爆炸机制

- **放置**：按空格在当前格子（Mathf.RoundToInt对齐网格）生成炸弹，bombCount--
- **倒计时**：炸弹等待bomBoomTime（初始2秒）后爆炸
- **十字爆炸**：以炸弹为中心，沿上下左右四个方向各延伸range格，生成爆炸特效
- **墙体阻挡**：爆炸延伸遇不可破坏墙（SuperWall）即break终止，不穿透
- **数量归还**：爆炸回调中bombCount++并从bombList移除，可再次放置
- **玩家站炸弹**：刚放置的炸弹不阻挡玩家，离开后不可再进入该格

### 2.4 胜负条件

- **过关**：消灭当前关卡所有敌人（enemyCount=0）→ 门可进入 → 接触门触发下一关
- **失败**：玩家HP降至0 → 死亡动画 → 游戏结束面板
- **时间压力**：每关有倒计时，时间归零且HP>0时HP--并重置时间为120秒；时间归零且HP=0时直接死亡

## 三、系统设计

### 3.1 玩家控制系统

#### 3.1.1 移动

- Rigidbody2D.MovePosition实现网格移动，速度由speed参数控制（初始0.1）
- 四方向动画（Up/Down/Left/Right），根据Input.GetAxis水平/垂直值切换
- 撞墙（SuperWall/Wall）被阻挡，不可穿墙

#### 3.1.2 属性系统

| 属性 | 初始值 | 上限 | 说明 |
|---|---|---|---|
| HP | 3 | - | 生命值，归零死亡 |
| range（爆炸范围） | 1 | - | 爆炸十字延伸格数 |
| bombCount（炸弹数量） | 1 | - | 可同时存在的炸弹数 |
| speed（移动速度） | 0.1 | 0.2 | 移动速度，拾取道具+0.03 |
| bomBoomTime（爆炸延时） | 2秒 | - | 炸弹放置到爆炸的时间 |

#### 3.1.3 受伤与无敌

- 玩家接触敌人或爆炸特效（BombEffect）时，如非无敌期则HP--
- 触发2秒无敌：协程Injured，每0.25秒交替透明度（0↔1），共2秒
- 无敌期isInjured=true，不重复受伤
- HP=0时触发PlayDieAni()：Time.timeScale=0，播放Die动画，动画结束后Destroy玩家并调用Gameover()

### 3.2 地图生成系统（MapController）

#### 3.2.1 地图结构

- **网格坐标系**：以整数坐标为格子单位，玩家/炸弹/墙均对齐网格
- **不可破坏墙（SuperWall）**：
  - 偶数坐标格（x+=2, y+=2）固定生成，形成网格骨架
  - 地图四周生成围墙封闭边界
  - 爆炸不可摧毁，阻挡爆炸延伸
- **可破坏墙（Wall）**：在空位点中随机生成，数量=wallCount（不超过空位数70%），可被炸弹炸毁
- **空地（NullPoint）**：玩家可移动、炸弹可放置的区域

#### 3.2.2 生成流程

```
InitMap(x, y, wallCount, enemyCount)
├── Recovery() — 清空上一关所有对象，回收到对象池
├── CreateSuperWall() — 生成偶数格骨架+边界围墙
├── FindNullPoints() — 计算所有可放置点位
│   └── 移除出生点周围3格（保证玩家安全）
├── CreateWall(wallCount) — 随机生成可破坏墙
├── CreateDoor() — 随机位置生成门（初始隐藏）
├── CreateProps() — 随机生成道具（0~2+空位数×5%个）
└── CreateEnemy(enemyCount) — 随机生成敌人
```

#### 3.2.3 出生点安全设计

- 玩家出生点固定在左上角：(-(X+1), Y-1)
- 移除出生点本身、右侧一格、下方一格的空位，确保不生成墙/敌人/道具
- 保证玩家首颗炸弹不会炸死自己，降低入门门槛

#### 3.2.4 地图尺寸公式

| 参数 | 公式 | 上限 |
|---|---|---|
| X（水平半宽） | 6 + 2 × (levelCount / 3) | 18 |
| Y（垂直半高） | 3 + 2 × (levelCount / 3) | 15 |

> levelCount为当前关卡数，每3关地图尺寸增大一次，达到上限后不再增大

### 3.3 道具系统（Prop）

| 道具类型 | 效果 | 说明 |
|---|---|---|
| 移速道具 | speed += 0.03 | 上限0.2，超过不再增加 |
| 炸弹数量道具 | bombCount++ | 可同时放置更多炸弹 |
| 爆炸范围道具 | range++ | 十字爆炸范围增大 |
| HP道具 | HP++ | 恢复1点生命值（如有） |

- 道具随机生成在空位中，玩家接触即拾取并回收到对象池
- 播放拾取音效（Pick）

### 3.4 敌人AI系统（EnemyAI）

- 敌人在随机空位生成，调用Init()初始化
- AI行为：随机移动/追踪玩家（按设计），不穿墙不卡墙
- 接触玩家（非无敌期）造成伤害
- 被炸弹爆炸命中：死亡，enemyCount--，回收到对象池
- 切关时全部回收到对象池

### 3.5 关卡递进系统（GameController）

#### 3.5.1 关卡参数公式

| 参数 | 公式 | 说明 |
|---|---|---|
| 初始时间 | levelCount × 50 + 90 | 关卡越深初始时间越长（但地图更大敌人更多，实际压力递增） |
| 敌人数 | (int)(levelCount × 1.5) + 1 | 最大20 |
| 地图尺寸 | X=6+2×(level/3), Y=3+2×(level/3) | 最大18×15 |

#### 3.5.2 过关流程（LevelCtrl）

```
LevelCtrl()
├── 设置时间 = levelCount×50+90
├── 计算地图尺寸X/Y（上限18/15）
├── 计算敌人数（上限20）
├── mapController.InitMap(x, y, x*y, enemyCount) — 生成新地图
├── 如玩家不存在则Instantiate并Init(range=1, HP=3, boomTime=2)
├── playerCtrl.ResetPlayer() — 清空炸弹、恢复透明度
├── 玩家位置 = mapController.GetPlayerPos()（左上角出生点）
├── 回收场上所有爆炸特效
├── 相机跟随初始化
├── levelCount++
└── UIController.PlayLevelFade(levelCount) — 播放关卡转场
```

#### 3.5.3 切关状态处理

- 玩家属性（HP/range/bombCount/speed）跨关卡保留，不重置
- 炸弹列表清空：所有炸弹StopAllCoroutines并回收到对象池，bombCount归还
- 玩家透明度恢复，无敌状态重置
- 场上所有敌人/墙/道具/特效回收到对象池

### 3.6 时间系统

- 每关倒计时，timer累加Time.deltaTime，每1秒time--
- UI实时刷新剩余时间
- time=0时：
  - HP>0 → HP--，time重置为120秒，游戏继续
  - HP=0 → 触发死亡动画，游戏结束
- 暂停菜单打开时倒计时应暂停（需确认timeScale协同）

### 3.7 对象池系统（ObjectPool）— 技术亮点

#### 3.7.1 设计结构

- **对象类型枚举（ObjectType）**：SuperWall、Wall、Prop、Bomb、Enemy、BombEffect 共6种
- **存储结构**：Dictionary<ObjectType, List<GameObject>> dic，每种类型一个对象列表
- **预制体映射**：List<Type_Prefab> type_Prefabs，序列化配置类型与预制体对应关系

#### 3.7.2 核心方法

**Get(type, pos) — 获取对象：**
1. 如dic中无该类型列表则创建
2. 如列表中有空闲对象则取出（RemoveAt末尾），否则Instantiate新对象
3. SetActive(true)，设置position/rotation，返回

**Add(type, go) — 回收对象：**
1. 如dic中有该类型且列表不包含该对象（Contains检查防重复），则加入列表
2. SetActive(false)

#### 3.7.3 设计优势

- 避免频繁Instantiate/Destroy导致的GC卡顿
- 重复回收保护（Contains检查）防止列表重复
- 切关时批量回收，poolObjectDic清空，无内存泄漏
- 6种对象类型统一管理，可扩展性强

### 3.8 UI系统

| UI元素 | 功能 |
|---|---|
| 开始界面（Start） | 游戏标题、开始按钮、设置按钮 |
| 游戏HUD | HP、关卡数、剩余时间、敌人数，实时刷新 |
| 暂停菜单（PauseMenu） | 继续/返回主菜单/退出 |
| 游戏结束面板（Gameover） | 显示游戏结束，背景音停止 |
| 关卡转场（LevelFade） | 过关时淡入淡出动画，显示关卡数 |

### 3.9 音效系统（AudioController）

| 音效 | 触发场景 |
|---|---|
| StartBackground | 开始界面背景音 |
| background/beijing | 游戏中背景音 |
| Fire | 放置炸弹 |
| Boom | 炸弹爆炸 |
| Pick | 拾取道具 |
| Click | UI按钮点击 |

- 游戏结束时audioSource.Stop()停止背景音
- 单例模式全局访问

## 五、关卡设计思路

### 5.1 难度曲线设计

本游戏采用**无尽关卡**模式，难度通过三个维度平滑递增：

1. **地图尺寸**：每3关增大一次，从6×3到最大18×15，探索空间逐渐增大
2. **敌人数量**：每关+1.5（取整），从1个到最大20个，压力逐渐增大
3. **时间压力**：初始时间虽递增（levelCount×50+90），但地图更大敌人更多，实际单位时间压力递增

> 设计原则：前3关为教学期（小地图少敌人），4-9关为成长期（地图逐步增大），12关后为挑战期（满地图满敌人，考验build和操作）

### 5.2 随机性与策略性

- 每关地图随机生成，墙/道具/敌人/门的位置均不固定
- 玩家需要根据当前地图布局规划炸弹放置位置和移动路线
- 道具build方向影响玩法：堆移速→游击打法、堆炸弹数→火力覆盖、堆范围→远程清场
- 敌人AI增加不确定性，需要临场应变

### 5.3 风险与奖励

- 炸毁可破坏墙可能获得道具（奖励），但也可能引出敌人（风险）
- 大范围炸弹清敌效率高，但也更容易炸到自己
- 快速清敌过关节省时间，但贪道具可能被敌人包围

## 六、美术与音效风格

### 6.1 美术风格

- **整体风格**：卡通像素风，色彩明亮，对比清晰
- **地图元素**：
  - 不可破坏墙（SuperWall）：深色硬质砖块，金属质感

- **炸弹**：经典圆形炸弹，引信闪烁动画
- **爆炸特效**：十字形火焰/冲击波动画
- **道具**：图标化设计，不同效果用颜色/形状区分

## 七、设计亮点与差异化

1. **程序化随机地图**：每关布局不同，重玩价值高，出生点安全区设计降低入门门槛
2. **对象池系统**：6种对象统一池化管理，含重复回收保护，长时间运行无内存泄漏，性能表现优秀
3. **经典十字爆炸**：遇不可破坏墙终止的精确逻辑，爆炸范围随range成长，build感强
4. **无尽关卡递进**：地图/敌人/时间三维度平滑递增，难度曲线合理，追求高关卡数
5. **双端输入支持**：PC键盘+移动端虚拟摇杆（Joystick Pack集成），代码预留可一键切换

## 一、项目概述

本项目是经典**炸弹人**玩法的 Unity 实现。玩家在程序化生成的网格地图中移动，放置炸弹产生十字形爆炸消灭敌人、炸毁可破坏墙，拾取道具提升属性（移速/炸弹数/爆炸范围），消灭所有敌人后找到隐藏的门进入下一关。关卡无尽递进，地图逐渐变大、敌人增多、时间收紧。

- **核心技术**：对象池系统（`ObjectPool`）、程序化地图生成（`MapController`）、单例模式全局管理
- **关卡机制**：无尽模式，地图最大 18×15，敌人最多 20，时间随关卡递增
- **玩家属性**：HP、爆炸范围（range）、炸弹数量（bombCount）、移动速度（speed）
- **输入方案**：PC 键盘（方向键+空格），移动端虚拟摇杆代码已预留
- **场景**：Start（开始界面）+ Game（游戏场景）

## 六、测试用例设计方法说明

本项目测试用例综合运用以下行业通用设计方法：

### 6.1 等价类划分

- **有效等价类**：正常方向输入、bombCount>0 时放炸弹、敌人全灭后进门、range 正常范围
- **无效等价类**：bombCount=0 放炸弹、敌人未全灭进门、超出地图范围的爆炸、重复回收对象

### 6.2 边界值分析

- **数值边界**：HP=0（死亡）、HP=1 受击（恰好死亡）、bombCount=0、range=1（最小）、range=10+（极大）、speed=0.2（上限）
- **地图边界**：第1关最小地图（6×3）、高关卡最大地图（18×15）、敌人全灭（enemyCount=0）、敌人上限（20）
- **时间边界**：time=0（归零扣血）、无敌期起止时刻、炸弹倒计时结束瞬间

### 6.3 场景法（流程分析）

- **核心循环**：移动→放炸弹→爆炸→杀敌→拾取道具→找到门→过关→下一关
- **死亡流程**：受伤→无敌闪烁→再次受伤→HP=0→死亡动画→游戏结束面板
- **切关流程**：敌人全灭→进门→旧对象回收→新地图生成→玩家重置→转场动画→继续游戏

### 6.4 错误推测法

- 炸弹爆炸瞬间切关导致协程残留
- 对象池重复回收导致列表异常
- 道具生成在不可达位置
- 玩家死亡瞬间过关导致状态冲突
- 高关卡大地图多爆炸导致性能问题
- 快速连续操作导致数值越界

### 6.5 判定表（多条件组合）

- 过关条件：enemyCount=0 且 玩家接触门 → 过关；否则不过关
- 时间归零：time=0 且 HP>0 → 扣血+重置时间；time=0 且 HP=0 → 死亡
- 受伤判定：接触伤害源 且 非无敌期 → 扣血+无敌；接触伤害源 且 无敌期 → 无效果

## 七、已知风险与测试建议

### 7.1 已识别风险

| 风险项 | 风险等级 | 说明 | 建议 |
|---|---|---|---|
| 程序化地图可达性 | 高 | 随机生成可能出现被 SuperWall 完全封闭的区域，导致门/道具不可达 | 增加可达性校验算法，或测试时多关卡抽样验证 |
| 玩家出生点安全性 | 中 | 虽代码移除了出生点周围3格，但敌人可能生成在附近快速击杀玩家 | 测试时关注首秒存活率，必要时增加出生保护 |
| 对象池协程残留 | 中 | 炸弹回收时调用 StopAllCoroutines，但切关时若有遗漏可能导致非活跃对象执行回调 | 切关时确保所有炸弹 StopAllCoroutines，增加断言检查 |
| 爆炸与可破坏墙交互 | 中 | 代码中 Boom 方法遇 SuperWall break，但未明确 Wall 是否阻挡，需确认设计意图 | 明确可破坏墙被炸毁后爆炸是否继续延伸，统一行为 |
| 移动端虚拟摇杆未启用 | 低 | 摇杆代码已写但注释，如发布移动端需启用并测试 | 启用后测试摇杆灵敏度、死区、多触点 |
| 时间系统与暂停 | 低 | 倒计时基于 Time.deltaTime，暂停时 timeScale 可能影响倒计时 | 确认暂停菜单是否设置 timeScale=0，倒计时是否正确暂停 |
| 无尽关卡性能 | 中 | 理论上可无限过关，对象池可能持续增长 | 长时间运行测试验证池大小稳定 |

### 7.2 测试建议

1. **优先测试核心循环**：放炸弹→爆炸→杀敌→过关，这是炸弹人最核心的体验
2. **重点关注爆炸逻辑**：十字范围、墙体阻挡、多炸弹重叠、连锁反应是 Bug 高发区
3. **地图生成需多轮抽样**：程序化生成的随机性意味着每次布局不同，建议每关至少重开 10 次观察
4. **对象池专项测试**：本项目对象池是技术亮点也是易错点，需重点验证复用、回收、泄漏
5. **边界值全覆盖**：HP=0、bombCount=0、敌人全灭、时间归零、地图最大尺寸，这些边界最易出 Bug
6. **大地图压力测试**：18×15 地图 + 20 敌人 + 多爆炸是最极端场景，必须验证性能
7. **建议录制复现视频**：随机生成的 Bug 难以复现，视频+种子（如有）是最有效的记录方式

### 8.4 测试总结与改进建议

本次测试覆盖了炸弹人的全部核心系统，共执行 145 条用例，通过率 94.5%，发现 8 个 Bug 其中 5 个已修复。游戏核心循环（移动→放炸弹→爆炸→杀敌→拾取道具→找门→过关→下一关）完整可用，无阻断性问题，对象池系统运行稳定，程序化地图生成经 100+ 次验证绝大多数合法可玩。

**主要优点：**
- 对象池系统设计规范，六种对象类型（SuperWall/Wall/Prop/Bomb/Enemy/BombEffect）均正确复用与回收，含重复回收保护（Contains 检查），长时间运行无内存泄漏，是本项目最大技术亮点
- 程序化地图生成逻辑清晰，SuperWall 偶数格固定骨架+随机可破坏墙+随机道具/敌人/门，出生点周围 3 格安全区设计合理
- 爆炸逻辑精确，十字范围延伸、遇不可破坏墙终止、边界不越界均正确，炸弹数量管理（bombCount 借出/归还）无异常
- 关卡递进数值公式正确（地图尺寸/敌人数/时间均符合设计公式），难度曲线平滑递增
- 玩家受伤无敌机制（2 秒闪烁）逻辑正确，无敌期内不重复扣血

**主要问题与改进建议：**
1. **地图可达性（最高优先级）**：建议增加 BFS 可达性校验，确保门和道具不会生成在被 SuperWall 封闭的不可达区域
2. **暂停与时间协同**：统一 PauseMenu 与 GameController 的 timeScale 管理，确保暂停时倒计时完全停止
3. **音效混音**：为 AudioController 增加同时播放数量限制和音量归一化，避免多炸弹同帧爆炸时爆音
4. **移动端验证**：虚拟摇杆代码已预留但注释，如计划发布移动端需启用并完成摇杆灵敏度/死区/多触点测试

**总体评价：有条件通过** — 核心玩法完整无阻断，对象池系统表现优秀，遗留问题均为非阻断性且有明确修复方案，建议增加地图可达性校验后发布。
